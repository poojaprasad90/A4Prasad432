PART 1 - THE BIG PICTURE (imagine you are sorting letters at a mailbox)
--------------------------------------------------------------------------------
The source file is one long string of characters: m a i n $ ( ) { ...
The scanner reads it ONE character at a time and groups characters into
"words" the compiler understands, called TOKENS.

  Example:  "main$"  -> one token: MNID_T   (a method name)
            "42"     -> one token: INL_T    (a number)
            "="      -> one token: ASS_T    (assignment)

Two ways it recognizes things:
  1. EASY single symbols ( ) { } ; = + - * / < >   -> decided instantly.
  2. HARD multi-letter things (names, numbers, strings, comments)
     -> decided with a STATE MACHINE (a map of "if you are here and see this,
        go there") until a whole word is complete.

When a whole word is found, a small "accept" function stamps it with the right
token label and hands it back.


PART 2 - MAP: FUNCTIONALITY  ->  EXACT CODE
--------------------------------------------------------------------------------

STEP 1. Get ready to scan
   What: reset counters, remember which buffer holds the source.
   Code: startScanner(BufferPointer psc_buf)
         - clears the token counts (scanHistogram)
         - sets sourceBuffer = psc_buf

STEP 2. Produce ONE token per call (the main worker)
   What: read a character; if it is an easy symbol, return its token now;
         otherwise run the state machine to read a whole word.
   Code: tokenizer()
         - c = readerGetChar(sourceBuffer);        // read one char
         - switch(c) { ... }                        // PART A: easy symbols
             ( -> LPR_T   ) -> RPR_T   { -> LBR_T   } -> RBR_T
             ; -> EOS_T   = -> ASS_T   + - * / -> ART_T   < > -> REL_T
             end-of-file  -> SEOF_T
         - default: { ... }                         // PART B: state machine

STEP 3. Turn a character into a "class" (a column number)
   What: letters, digits, ".", "$", etc. are grouped so the table stays small.
   Code: nextClass(c)
         letter->0  digit->1  _->2  $->3  "->4  EOF->5  ~->6  .->7  other->8

STEP 4. Move through the state machine
   What: from the current state + the character class, look up the next state.
   Code: nextState(state, c)
         - col  = nextClass(c);
         - next = transitionTable[state][col];      // the map lookup
     The loop in tokenizer() keeps calling nextState until it lands on a
     FINAL (accepting) state; then it copies the word into lexemeBuffer.

STEP 5. Stamp the finished word with the correct token (accept functions)
   What: each final state points to one function that builds the token.
   Code: finalStateTable[state] -> one of:

     funcID(lexeme)   -> ends with "$"      => MNID_T (method id)
                         is a keyword        => KW_T   (vault, whole, logic...)
                         otherwise           => AVID_T (variable name: x, msg)
     funcIL(lexeme)   -> digits              => INL_T  (integer, e.g. 42)
     funcFPL(lexeme)  -> digits "." digits   => FPL_T  (float, e.g. 3.14)
     funcSL(lexeme)   -> "...."              => STR_T  (string; text saved in
                                                        stringLiteralTable)
     funcCMT(lexeme)  -> ~....~              => CMT_T  (comment)
     funcKEY(lexeme)  -> checks keyword list (helper used for keywords)
     funcErr(lexeme)  -> anything illegal    => ERR_T  (never crashes)

STEP 6. Print each token
   What: show the token name (and its value if it has one).
   Code: printToken(t)  -> switch(t.code) prints "INL_T   42", "AVID_T  x", etc.


PART 3 - WHAT I ADDED IN A3 (the starter only knew "Hello World")
--------------------------------------------------------------------------------
Before: names, numbers and "=" all came out as ERR_T.
I extended the machine so real Scribe tokens are recognized:

  + Variable names (AVID_T)   -> in funcID (non-keyword => AVID_T)
  + Integers (INL_T)          -> table now sends digits to funcIL
  + Floats (FPL_T)            -> new "." column + funcFPL
  + Operators = + - * / < >   -> new cases in tokenizer()"s switch

Result: hello.scr now scans with ZERO ERR_T, and bad input (@, unterminated
strings) still safely becomes ERR_T without crashing.
