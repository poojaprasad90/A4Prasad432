This document defines the lexical specification of the Scribe scanner BEFORE
coding, as required by the A3 specification:
   "The Scanner to be implemented will use RE (Regular Expressions) and the TD
    (Transition Table) that you need to develop BEFORE coding."

It describes, in order:
   1. Character classes (transition-table columns)
   2. Token classes recognized
   3. Regular Expressions (RE) for each transition-table token
   4. Transition Diagram (the automaton / DFA)
   5. Transition Table (the coded form of the diagram)
   6. Accepting states and their acceptance functions
   7. Token-driven tokens (recognized outside the DFA)


================================================================================
 1. CHARACTER CLASSES  (columns of the transition table)
================================================================================

The scanner maps every input character to ONE class. Each class is a column
in the transition table. There are 9 classes (CHAR_CLASSES = 9):

   Col  Symbol  Class name        Members
   ---  ------  ----------------  --------------------------------------------
    0    L      Letter            A-Z a-z          (isalpha)
    1    D      Digit             0-9              (isdigit)
    2    U      Underscore        _
    3    M      Dollar            $                (method-id marker)
    4    Q      Quote             "                (string delimiter)
    5    E      SEOF              \0 (EOS) , 0xFF (EOF)
    6    C      Tilde              ~                (comment delimiter)
    7    P      Period            .                (decimal point)
    8    O      Other             any other visible char

Implemented by function: nextClass(c)  in Step3Scanner.c


================================================================================
 2. TOKEN CLASSES
================================================================================

Recognized by the TRANSITION TABLE (DFA):
   MNID_T   Method identifier          e.g. main$  print$
   AVID_T   Variable identifier        e.g. x  msg  counter
   KW_T     Keyword                    e.g. vault whole text logic giveback
   INL_T    Integer literal            e.g. 42  100
   FPL_T    Floating-point literal     e.g. 3.14  0.5
   STR_T    String literal             e.g. "Hello world!"
   CMT_T    Comment                    e.g. ~ a comment ~
   ERR_T    Error token                illegal / malformed lexeme

Recognized by TOKEN-DRIVEN code (single characters, see section 7):
   LPR_T (  RPR_T )  LBR_T {  RBR_T }  EOS_T ;
   ASS_T =   ART_T + - * /   REL_T < >
   SEOF_T (\0 / 0xFF)


================================================================================
 3. REGULAR EXPRESSIONS (RE)
================================================================================

Auxiliary definitions:
   letter  = [A-Za-z]
   digit   = [0-9]
   idchar  = letter | digit | _

--- Method identifier (MNID) -------------------------------------------------
   MNID = letter (idchar)* $

   A run of identifier characters that TERMINATES with "$".
   Example: main$   print$

--- Variable identifier / Keyword (AVID / KW) --------------------------------
   VID  = letter (idchar)*

   A run of identifier characters NOT ending in "$". After the lexeme is read,
   it is looked up in the keyword table:
      - if it matches a keyword  -> KW_T
      - otherwise                -> AVID_T
   Constraint: length <= VID_LEN (20). Longer -> ERR_T (defensive).
   Example: x  msg  (AVID)   ;   vault whole text logic giveback (KW)

--- Integer literal (IL) -----------------------------------------------------
   IL = digit+

   One or more digits, not followed by a ".".
   Constraint: 0 <= value <= SHRT_MAX and length <= NUM_LEN (5); else ERR_T.
   Example: 42  100  32767

--- Floating-point literal (FPL) ---------------------------------------------
   FPL = digit+ . digit+

   Digits, a decimal point, then one or more fraction digits.
   ("42." with no fraction digit is malformed -> ERR_T.)
   Example: 3.14  0.5  100.0

--- String literal (SL) ------------------------------------------------------
   SL = " (any char except ")* "

   Opening quote, body, closing quote. If EOF is reached before the closing
   quote -> ERR_T (unterminated string).
   Example: "Hello world!"

--- Comment (CMT) ------------------------------------------------------------
   CMT = ~ (any char except ~)* ~

   Opening hash, body, closing hash. Unterminated at EOF -> ERR_T.
   Example: ~ this is a comment ~


================================================================================
 4. TRANSITION DIAGRAM (DFA)
================================================================================

Legend:  (Sn) = state n     [ACCEPT] = accepting state
         ->   = transition   "else" = any class not shown on other arrows

States overview:
   S0  start
   S1  identifier body           S2  [ACCEPT MNID]   S3  [ACCEPT VID/KW, retract]
   S4  string body               S5  [ACCEPT SL]
   S6  comment body              S7  [ACCEPT CMT]
   S8  [ACCEPT ERR, no retract]  S9  [ACCEPT ERR, retract]
   S10 integer body              S13 [ACCEPT IL, retract]
   S11 seen "."                  S12 fraction body     S14 [ACCEPT FPL, retract]

------------------------------------------------------------------------------
 Identifiers / keywords / method-ids:

        letter                 $
   (S0) ------> (S1) ---------------> (S2)[ACCEPT MNID]
                 |  ^                     (no retract)
        idchar   |  | idchar
                 +--+
                 |
                 | else (not idchar, not $)
                 v
               (S3)[ACCEPT VID or KW]  (retract 1 char)
                    -> keyword table? KW_T : AVID_T

------------------------------------------------------------------------------
 Integer and floating-point literals:

        digit               digit
   (S0) -----> (S10) --------------> (S10)   (loop on digits)
                 |  \
          else   |   \ "."
        (retract)|    v
                 v   (S11) --digit--> (S12) --digit--> (S12)  (loop)
              (S13)     |                  |
           [ACCEPT IL]  | else             | else (retract)
                        | (retract, error) v
                        v               (S14)[ACCEPT FPL]
                     (S9)[ERR]

------------------------------------------------------------------------------
 String literal:                        Comment:

        "                                     ~
   (S0) --> (S4) --not "--> (S4)         (S0) --> (S6) --not ~--> (S6)
             |  loop                              |  loop
         "   |                                ~   |
             v                                    v
          (S5)[ACCEPT SL]                      (S7)[ACCEPT CMT]

   (EOF inside S4 or S6 -> error state -> ERR_T : unterminated)


================================================================================
 5. TRANSITION TABLE   (NUM_STATES = 15, CHAR_CLASSES = 9)
================================================================================

Cell values:
   number = go to that state
   ESNR (8) = error state, no retract
   ESWR (9) = error state, with retract
   FS   (99)= illegal / unused cell (never reached from an accepting state)

         L(0)  D(1)  U(2)  M(3)  Q(4)  E(5)  C(6)  P(7)  O(8)
         [A-z] [0-9]  _     $     "    SEOF   ~     .    other
  S00 :    1    10   ESNR  ESNR   4    ESWR   6    ESNR  ESNR   start
  S01 :    1     1    1     2     3     3     3     3     3     ident body
  S02 :   FS    FS   FS    FS    FS    FS    FS    FS    FS     ACCEPT MNID
  S03 :   FS    FS   FS    FS    FS    FS    FS    FS    FS     ACCEPT VID/KW
  S04 :    4     4    4     4     5    ESWR   4     4     4     string body
  S05 :   FS    FS   FS    FS    FS    FS    FS    FS    FS     ACCEPT SL
  S06 :    6     6    6     6     6    ESWR   7     6     6     comment body
  S07 :   FS    FS   FS    FS    FS    FS    FS    FS    FS     ACCEPT CMT
  S08 :   FS    FS   FS    FS    FS    FS    FS    FS    FS     ACCEPT ERR (nr)
  S09 :   FS    FS   FS    FS    FS    FS    FS    FS    FS     ACCEPT ERR (wr)
  S10 :   13    10   13    13    13    13    13    11    13     integer body
  S11 : ESWR    12  ESWR  ESWR  ESWR  ESWR  ESWR  ESWR  ESWR    seen "."
  S12 :   14    12   14    14    14    14    14    14    14     fraction body
  S13 :   FS    FS   FS    FS    FS    FS    FS    FS    FS     ACCEPT IL
  S14 :   FS    FS   FS    FS    FS    FS    FS    FS    FS     ACCEPT FPL

Implemented as: transitionTable[NUM_STATES][CHAR_CLASSES] in Step3Scanner.h


================================================================================
 6. ACCEPTING STATES AND ACCEPTANCE FUNCTIONS
================================================================================

   State  Type   Retract?  Function     Produces
   -----  -----  --------  -----------  ------------------------------------
   S02    FSNR   no        funcID       MNID_T (lexeme ends with "$")
   S03    FSWR   yes       funcID       KW_T (keyword) or AVID_T (variable)
   S05    FSNR   no        funcSL       STR_T (stored in string literal table)
   S07    FSNR   no        funcCMT      CMT_T
   S08    FSNR   no        funcErr      ERR_T
   S09    FSWR   yes       funcErr      ERR_T
   S13    FSWR   yes       funcIL       INL_T (range-checked <= SHRT_MAX)
   S14    FSWR   yes       funcFPL      FPL_T (range-checked <= FLT_MAX)

   State types:  NOFS=0 (not accepting)  FSNR=1 (accept, no retract)
                 FSWR=2 (accept, with retract)

Implemented as: stateType[] and finalStateTable[] in Step3Scanner.h


================================================================================
 7. TOKEN-DRIVEN TOKENS  (recognized directly, outside the DFA)
================================================================================

These single characters are handled in the tokenizer() switch (Part 1),
before the transition-table driven part (Part 2):

   Character   Token     Attribute
   ---------   -------   ------------------------------
   (           LPR_T     -
   )           RPR_T     -
   {           LBR_T     -
   }           RBR_T     -
   ;           EOS_T     -
   =           ASS_T     -
   + - * /     ART_T     OP_ADD / OP_SUB / OP_MUL / OP_DIV
   < >         REL_T     OP_LT / OP_GT
   \0          SEOF_T    SEOF_0
   0xFF        SEOF_T    SEOF_255
   space,tab   (skipped)
   newline     (skipped, line counter incremented)


================================================================================
 8. DESIGN NOTES / DEFENSIVE PROGRAMMING
================================================================================

 - Illegal / unrecognized characters (e.g. @ ? $) reach the error states
   (ESNR / ESWR) and produce ERR_T; the scanner does NOT crash and continues
   with the next token.
 - Unterminated strings and comments (EOF before the closing " or ~) reach an
   error state -> ERR_T.
 - Integer literals over SHRT_MAX or NUM_LEN digits -> ERR_T.
 - Identifiers longer than VID_LEN (20) -> ERR_T.
 - The scanner recognizes one token per call to tokenizer(); the parser (A4)
   will request tokens one at a time.
